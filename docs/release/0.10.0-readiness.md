# Release Akasha Code Studio 0.10.0

État relevé le 24 octobre 2026. La PR de préparation #115 est fusionnée, Akasha v0.12.0 est publiée, et le tag annoté `v0.10.0` pointe sur le commit fusionné. Le paquet `akasha-code-studio@0.10.0` n'est pas encore disponible sur npm.

## État de la publication

- La CI de la PR #115 a réussi sur Linux et Windows.
- Le secret GitHub Actions `NPM_TOKEN` est présent et est un jeton npm stage-only.
- Le premier essai (workflow [40032152337](https://github.com/azerothl/Akasha-code-studio/actions/runs/40032152337)) a réussi pour la vérification du tag, `npm ci` et `npm test`, puis npm a refusé `npm publish` direct avec `E_STAGE_REQUIRED`.
- Le workflow est donc ajusté pour soumettre la version avec `npm stage publish`. Une personne mainteneuse devra examiner le stage et l'approuver avec 2FA avant que `0.10.0` soit public et installable.
- Comme le paquet est nouveau, npm peut rendre visible un paquet de remplacement `0.0.0-stage` dès la création du stage; le contenu de `0.10.0` reste indisponible avant son approbation.

## Déclenchement et validation

Le tag `v0.10.0` existe déjà; il ne faut pas le déplacer ni le recréer. Après fusion du correctif de workflow, le lancer manuellement depuis `main` avec la version `v0.10.0`. Le workflow vérifie le tag et la version de `package.json`, installe npm CLI 11.15.0, exécute `npm ci` et `npm test`, puis crée le stage public. L'approbation 2FA se fait ensuite dans l'onglet Staged Packages de npm ou avec `npm stage approve <stage-id>`.

Le test Todo avec un vrai LLM a exercé le Kanban et observé des reprises, mais n'a pas livré une application complète avec tests et aperçu validés. Cette release ne prétend pas garantir une autonomie complète. Voir le rapport du 23 octobre dans `docs/validation/inspection-handoff-vitest-real-2026-10-23.md`.
